# 마커 장부

`develop_rule` 스킬의 참조 문서. `/develop_rule debt` 로 들어온다.

의도적으로 감수한 한계는 코드에 마커로 남긴다. 이 모드는 흩어진 마커를 한 장부로 모아, 미뤄둔 것이 조용히 영구화되는 걸 막는다.

---

## 두 개의 태그, 하나의 장부

| 마커 | 무엇을 표시하나 | 형식 |
|---|---|---|
| `ponytail:` | 의도적 단순화. 성능·확장의 알려진 천장이 있는 선택 | `# ponytail: <천장>, <업그레이드 조건>` |
| `idempotent:` | 의도적 비멱등. 다시 실행하면 상태가 달라지는 지점 | `# idempotent: <이유>, <해결 방법>` |

둘은 다른 사실을 표시하므로 접두사를 합치지 않는다. 대신 **장부는 하나**다. 미뤄둔 판단이 어디에 몇 개 있는지를 한 화면에서 봐야 하기 때문이다.

## 수집

`node_modules`, `.git`, 빌드 산출물을 빼고 주석 마커를 훑는다.

```bash
grep -rnE '(#|//) ?(ponytail|idempotent):' .
```

스택이 다른 주석 접두사를 쓰면 추가한다. 주석 접두사를 요구하는 이유는, 이 규약을 그냥 언급하기만 한 산문이 장부에 섞이지 않게 하기 위해서다.

발견 하나가 장부 한 줄이다.

## 출력

파일별로 묶어서 한 줄씩.

```
<file>:<line>  [ponytail]  <무엇을 단순화했나>. 천장: <명시된 한계>. 조건: <다시 볼 트리거>.
<file>:<line>  [idempotent] <무엇이 비멱등인가>. 이유: <왜>. 해결: <어떻게>.
```

마커 형식이 `<태그>: <천장>, <업그레이드 조건>` 이므로 두 조각을 주석에서 그대로 뽑는다. 줄마다 담당자까지 필요하면 `git blame -L<line>,<line>` 을 붙인다.

**썩을 위험을 표시한다.** 업그레이드 경로나 트리거를 적지 않은 마커에는 `no-trigger` 태그를 단다. 조용히 썩는 건 이쪽이다.

마무리: `<N>개 마커, 그중 <M>개는 트리거 없음.` 아무것도 없으면 `장부 비어 있음. 미뤄둔 것 없음.`

## 범위 밖

읽고 보고만 한다. 아무것도 고치지 않는다. 파일로 남기고 싶다면 물어본 뒤 `DEVELOP-DEBT.md` 에 쓴다. 단발 모드다.
