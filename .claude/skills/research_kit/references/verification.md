# 3단계: 검증

`research_kit` 의 참조 문서. 설계가 확정됐고 실험을 돌릴 때 읽는다.

이 단계의 산출물은 `research/<slug>/experiments/<exp-id>/` 아래의 실험 코드, `runs/<run-id>/` 폴더들, `figures/` 다. 실행 하나당 폴더 하나, 폴더마다 `card.md`.

---

## 시작 전 확인

`design.md` 의 "끝내기 전 확인" 항목이 다 채워졌는지 본다. 평가 기준이나 임계값이 비어 있으면 실행하지 않고 사용자에게 알린다. 결과를 본 뒤 기준을 정하는 걸 막는 유일한 시점이 지금이다.

## 실험 코드

실험마다 `experiments/<exp-id>/` 에 코드 하나를 둔다. 설계에서 정한 형태를 따른다.

### 공통 규칙

모듈이든 노트북이든 같다.

- **seed 고정이 코드 첫머리에 있다.** `set_seed(seed)` 를 모델 로드와 데이터 셔플보다 먼저 부른다. seed 는 하드코딩하지 않고 인자나 설정에서 받는다.
- **진행바.** 항목이나 스텝을 도는 루프는 `tqdm` 으로 감싼다. 긴 실행이 멈췄는지 느린지 구분하기 위해서다. 로그 파일로 돌릴 때는 `tqdm(..., file=sys.stderr, mininterval=10)` 처럼 갱신 간격을 늘린다.
- **항목 단위 출력.** 결과는 `runs/<run-id>/metrics.jsonl` 에 항목 하나당 한 줄로 쓴다. 평균만 저장하면 평가 단계에서 오답을 읽거나 추출 실패를 세지 못한다. LLM 평가면 한 줄에 최소 `{"id": ..., "prediction": ..., "gold": ..., "raw": ...}`. `raw` 는 모델의 원 응답 전체다. 채점을 다시 해도 API 를 다시 부르지 않게 한다.
- **설정은 파일로.** 조건을 가르는 값(모델, 프롬프트, temperature, 학습률)은 코드 안이 아니라 설정 파일이나 인자에 있고, 실행 시 `runs/<run-id>/config.*` 로 복사된다.
- **그림은 `figures/` 에.** 보고서에 들어갈 그림은 `figures/<exp-id>-<내용>.png` 로 저장한다. 제목, 축 이름, 단위, 조건 범례가 그림 안에 있어야 한다. 보고서 밖으로 떼어내도 무엇인지 알 수 있게.
- **외부 서비스는 보조.** W&B, MLflow 를 이미 쓰고 있으면 그대로 쓰고 run URL 을 카드에 적는다. 그래도 `metrics.jsonl` 은 로컬에 남긴다. 외부 서비스는 사라지거나 권한이 바뀐다.

### 모듈 (`run.py`)

기본 형태다. `assets/run_template.py` 를 복사해 시작한다. 템플릿은 인자 파싱, seed 고정, tqdm 루프, jsonl 기록, 실행 폴더 생성까지 갖추고 있고, 모델 호출과 채점 부분만 비어 있다.

```bash
python experiments/<exp-id>/run.py --config configs/prop.yaml --seed 0 --run-dir experiments/<exp-id>/runs/<run-id>
```

seed 여러 개는 셸 루프로 돌린다. 실행 명령을 카드에 그대로 적을 수 있어서 모듈을 기본으로 한다.

### 노트북 (`run.ipynb`)

사용자가 탐색적으로 보면서 돌리고 싶을 때 쓴다. 추가 규칙:

- 첫 셀에 설정과 seed, 둘째 셀에 `set_seed`. 그 아래는 위에서 아래로 한 번 실행하면 끝까지 돈다.
- **Restart & Run All 이 통과해야 결과로 인정한다.** 셀을 순서 없이 돌려 나온 결과는 재현할 수 없다. 카드에 실행 명령 대신 "Restart & Run All, <날짜>"를 적는다.
- 결과 기록은 모듈과 같다. 노트북 출력 셀에만 남은 숫자는 결과가 아니다. `metrics.jsonl` 과 `figures/` 에 저장한다.
- 노트북을 명령줄로 돌릴 수 있으면(`jupyter nbconvert --execute` 또는 `papermill`) 그 명령을 카드에 적는다.

## run-id

`<조건ID>-s<seed>-<YYYYMMDD>-<짧은 git hash>` 형식. 예: `prop-s1-20260924-a1b2c3d`.

이름만 보고 어느 조건, 어느 seed, 어느 코드로 돌렸는지 알 수 있게 하기 위해서다. 같은 run-id 폴더가 이미 있으면 덮어쓰지 않는다. 같은 조건을 다시 돌려야 하면 뒤에 `-r2` 를 붙인다.

run-id 는 카드를 만들 때 한 번 정하고, 실행 명령에 그 값을 그대로 넘긴다. 실행 스크립트가 날짜나 해시를 실행 시점에 다시 계산하면 계획 카드가 있는 폴더와 결과가 쌓이는 폴더가 갈라진다.

## 실행 카드: 모든 실행에 필수

`assets/experiment-card.md` 를 `runs/<run-id>/card.md` 로 복사해 채운다. 실행 **전에** 계획 상태로 만들고, 실행 뒤 결과를 채운다. 실행 전에 만드는 이유는, 실행이 중간에 죽어도 무엇을 돌리려 했는지는 남기기 위해서다.

반드시 채우는 것:

- **실행 명령**: 실제로 친 명령을 그대로. 셸 변수는 풀어서. 노트북이면 "Restart & Run All" 과 날짜.
- **config 사본**: 실행에 쓴 설정 파일을 `runs/<run-id>/` 로 복사한다. 원본 경로만 적으면 나중에 그 파일이 바뀐다.
- **git commit**: `scripts/snapshot_env.sh` 로 뽑는다. 작업 트리에 커밋 안 된 변경이 있으면 스크립트가 "재현 불가"로 표시한다. 이때는 먼저 커밋하자고 제안하고, 사용자가 그대로 돌리겠다고 하면 카드의 구분을 **탐색**으로 적는다.
- **seed**: 코드에서 실제로 설정되는 모든 seed(Python `random`, NumPy, PyTorch, CUDA, 데이터 셔플, API 의 `seed` 파라미터).
- **데이터 버전**: 파일 해시(`shasum -a 256`) 또는 데이터셋 이름 + revision.
- **환경**: `bash {skill_dir}/scripts/snapshot_env.sh <저장소 경로>` 출력을 그대로 붙인다.

snapshot 스크립트는 읽기만 하므로 몇 번 돌려도 안전하다.

## seed 고정

PyTorch 가 들어가면 코드에 아래가 있는지 확인하고, 없으면 추가를 제안한다. `assets/run_template.py` 에 같은 함수가 있다.

```python
import os, random
import numpy as np

def set_seed(seed: int) -> None:
    random.seed(seed)
    np.random.seed(seed)
    os.environ["PYTHONHASHSEED"] = str(seed)
    try:
        import torch
        torch.manual_seed(seed)
        torch.cuda.manual_seed_all(seed)
    except ImportError:
        pass
```

완전한 비트 단위 재현이 필요하면 `torch.use_deterministic_algorithms(True)` 도 있지만 느려지고 일부 연산이 막힌다. 보통은 seed 고정 + seed 여러 개로 분산을 보고하는 쪽이 현실적이다. 어느 쪽을 쓸지는 설계에 적힌 대로 따른다.

LLM API 는 temperature 0 이어도 출력이 완전히 같지 않을 수 있다. API 가 `seed` 파라미터를 받으면 넘기고, 원 응답을 전부 저장한다.

## 작게 먼저

전체 실행 전에 스모크 테스트를 한다.

- 평가: 항목 5~10개로 끝까지. 호출, 답 추출, 채점, `metrics.jsonl` 저장, 그림 저장까지
- 학습: 스텝 수십 개로. 손실이 줄어드는지, 체크포인트가 저장되는지, 평가 루프가 도는지

스모크 테스트는 `runs/` 에 넣지 않는다. 결과가 아니라 배관 점검이다. 스모크 테스트에서 답 추출이 이상하게 나오면(정답인데 오답 처리 등) 전체 실행 전에 고친다. 이게 가장 비싼 실수를 막는다.

스모크 테스트에서 **설계의 산출 규칙이 실제 출력에 안 맞는 것**이 보이면(예: 모델이 `####` 형식을 안 지킴) 규칙을 조용히 고치지 않는다. 사용자에게 알리고, 바꾸면 `design.md` 의 변경 이력에 남긴다.

## 실행 중 기록

- 긴 실행은 백그라운드로 돌리고 로그 파일로 진행을 본다.
- 실행 중 이상(손실 발산, 추출 실패 급증, 호출 오류 반복)이 보이면 멈추고 카드 메모에 적는다. 끝까지 돌린 뒤 버리는 것보다 싸다.

## 실패 처리

실패한 실행도 폴더를 지우지 않는다. 카드 상태를 **실패**로 바꾸고 메모에 어느 단계에서 무엇 때문에 죽었는지 적는다. 원인을 고쳐 다시 돌리면 새 run-id(`-r2`)로 만든다.

## 끝내기 전 확인

`design.md` 의 실험 × 조건 × seed 조합이 `runs/` 에 모두 **완료**로 있는지 표로 확인한다.

```
| 실험 | 조건 | s0 | s1 | s2 |
|---|---|---|---|---|
| exp1 | base | 완료 | 완료 | 완료 |
| exp1 | prop | 완료 | 실패 | - |
```

빈칸이 있으면 4단계로 넘어가기 전에 사용자에게 알린다. 빠진 조합을 두고 평가하면 조건 간 비교가 공정하지 않다. 설계에 적은 그림이 `figures/` 에 다 있는지도 같이 본다.
