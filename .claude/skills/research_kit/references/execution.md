# 3단계 — 실행·로깅

`research_kit` 의 참조 문서. 설계가 확정됐고 실험을 돌릴 때 읽는다.

이 단계의 산출물은 `research/<slug>/runs/<run-id>/` 폴더들이다. 실행 하나당 폴더 하나, 폴더마다 `card.md`.

---

## 시작 전 확인

`design.md` 의 "끝내기 전 확인" 항목이 다 채워졌는지 본다. 판정 기준이 비어 있으면 실행하지 않고 사용자에게 알린다 — 결과를 본 뒤 기준을 정하는 걸 막는 유일한 시점이 지금이다.

## run-id

`<조건ID>-s<seed>-<YYYYMMDD>-<짧은 git hash>` 형식. 예: `prop-s1-20260924-a1b2c3d`.

이름만 보고 어느 조건, 어느 seed, 어느 코드로 돌렸는지 알 수 있게 하기 위해서다. 같은 run-id 폴더가 이미 있으면 덮어쓰지 않는다. 같은 조건을 다시 돌려야 하면 뒤에 `-r2` 를 붙인다.

## 재현성 기록 — 모든 실행에 필수

`assets/experiment-card.md` 를 `runs/<run-id>/card.md` 로 복사해 채운다. 실행 **전에** 계획 상태로 만들고, 실행 뒤 결과를 채운다. 실행 전에 만드는 이유는, 실행이 중간에 죽어도 무엇을 돌리려 했는지는 남기 위해서다.

반드시 채우는 것:

- **실행 명령** — 실제로 친 명령을 그대로. 셸 변수는 풀어서.
- **config 사본** — 실행에 쓴 설정 파일을 `runs/<run-id>/` 로 복사한다. 원본 경로만 적으면 나중에 그 파일이 바뀐다.
- **git commit** — `scripts/snapshot_env.sh` 로 뽑는다. 작업 트리에 커밋 안 된 변경이 있으면 스크립트가 "재현 불가"로 표시한다. 이때는 먼저 커밋하자고 제안하고, 사용자가 그대로 돌리겠다고 하면 카드의 구분을 **탐색**으로 적는다.
- **seed** — 코드에서 실제로 설정되는 모든 seed(Python `random`, NumPy, PyTorch, CUDA, 데이터 셔플, API 의 `seed` 파라미터).
- **데이터 버전** — 파일 해시(`shasum -a 256`) 또는 데이터셋 이름 + revision.
- **환경** — `bash {skill_dir}/scripts/snapshot_env.sh <저장소 경로>` 출력을 그대로 붙인다.

snapshot 스크립트는 읽기만 하므로 몇 번 돌려도 안전하다.

## seed 고정 확인

PyTorch 학습이면 코드에 아래가 있는지 확인하고, 없으면 추가를 제안한다.

```python
import random, numpy as np, torch
def set_seed(seed: int):
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.cuda.manual_seed_all(seed)
```

완전한 비트 단위 재현이 필요하면 `torch.use_deterministic_algorithms(True)` 도 있지만 느려지고 일부 연산이 막힌다. 보통은 seed 고정 + seed 여러 개로 분산을 보고하는 쪽이 현실적이다. 어느 쪽을 쓸지는 설계에 적힌 대로 따른다.

LLM API 평가면 temperature 0 이어도 출력이 완전히 같지 않을 수 있다. 원 응답 텍스트를 전부 저장해서, 채점을 다시 해도 API 를 다시 부르지 않게 한다.

## 작게 먼저

전체 실행 전에 스모크 테스트를 한다.

- 평가: 항목 5~10개로 끝까지 — 호출, 답 추출, 채점, 지표 저장까지
- 학습: 스텝 수십 개로 — 손실이 줄어드는지, 체크포인트가 저장되는지, 평가 루프가 도는지

스모크 테스트는 `runs/` 에 넣지 않는다. 결과가 아니라 배관 점검이다. 스모크 테스트에서 답 추출이 이상하게 나오면(정답인데 오답 처리 등) 전체 실행 전에 고친다 — 이게 가장 비싼 실수를 막는다.

## 실행 중 기록

- 지표는 `runs/<run-id>/metrics.jsonl` 에 항목 단위로 쓴다. 평균만 저장하면 4단계에서 쌍체 분석과 bootstrap 을 할 수 없다. LLM 평가면 한 줄에 `{"id": ..., "prediction": ..., "gold": ..., "correct": ...}`.
- W&B·MLflow 같은 추적 도구를 이미 쓰고 있으면 그대로 쓰고, run URL 을 카드에 적는다. 추적 도구가 있어도 `metrics.jsonl` 은 로컬에 남긴다 — 외부 서비스는 사라지거나 권한이 바뀐다.
- 긴 실행은 백그라운드로 돌리고 로그 파일로 진행을 본다.

## 실패 처리

실패한 실행도 폴더를 지우지 않는다. 카드 상태를 **실패**로 바꾸고 메모에 어느 단계에서 무엇 때문에 죽었는지 적는다. 원인을 고쳐 다시 돌리면 새 run-id(`-r2`)로 만든다.

## 끝내기 전 확인

`design.md` 의 조건 × seed 조합이 `runs/` 에 모두 **완료**로 있는지 표로 확인한다.

```
| 조건 | s0 | s1 | s2 |
|---|---|---|---|
| base | 완료 | 완료 | 완료 |
| prop | 완료 | 실패 | - |
```

빈칸이 있으면 4단계로 넘어가기 전에 사용자에게 알린다. 빠진 조합을 두고 분석하면 조건 간 비교가 공정하지 않다.
