# aar

끝난 작업을 After Action Review 네 질문으로 돌아보고, 교훈을 다음 세션이 실제로 읽는 파일에 반영한다.

```
/aar          # 방금 끝난 작업이나 세션을 회고
```

"회고하자", "이번 세션 돌아보자", "같은 실수 안 하게 해줘"로도 켜진다. 요청에 "바로 적용해"가 있으면 승인 질문 없이 반영한다.

## 하는 일

1. 네 질문에 답한다: 무엇을 기대했나, 실제로 무엇이 일어났나, 왜 달랐나, 다음엔 무엇을 하나. 기억이 아니라 대화 기록, 에러, git 이력을 근거로 쓴다.
2. 검증 가능한 교훈을 0개에서 3개 뽑는다. 특정 도구, 명령, 숫자, 파일, 조건이 없는 교훈은 버린다.
3. 다음 세션이 같은 실수를 반복할 교훈만 수정 계획으로 만든다. 대상 파일과 넣을 문장을 정확히 쓴다.
4. 중복을 확인하고, 승인받은 뒤 반영한다.

## 저장 위치

별도 LESSONS 파일을 만들지 않는다. 다음 세션이 자동으로 읽는 곳에 넣는다.

| 범위 | 대상 |
|---|---|
| 이 프로젝트의 규칙 | 프로젝트 `CLAUDE.md` |
| 특정 스킬의 절차 | 그 스킬의 `SKILL.md` |
| 사용자의 작업 방식과 선호 | Claude Code 메모리 |
| 모든 프로젝트 공통 | `~/.claude/CLAUDE.md` |

## 하지 않는 일

- 승인 없이 파일을 고치지 않는다.
- 맥락뿐인 교훈으로 규칙 파일을 채우지 않는다.
- 프로덕션 장애의 공식 포스트모템 문서를 쓰지 않는다.
