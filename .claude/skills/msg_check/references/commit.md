# 커밋 메시지 규칙

`msg_check` 의 참조 문서. 검수 대상이 커밋 메시지일 때 읽는다.

---

## 형식

Conventional Commits 를 따르고, 설명 부분은 항상 한국어로 쓴다. `type` 과 `scope` 는 영어 소문자 그대로 둔다 — 도구(changelog 생성기, 릴리스 봇)가 이 부분을 파싱하기 때문이다.

```
<type>(<scope>): <한국어 요약>

- <작업한 문제 및 기능>
- <작업한 결과>
- <특이사항>   ← 있을 때만
```

## 제목 줄

- `type` 은 다음 중 하나: `feat` `fix` `refactor` `perf` `docs` `test` `build` `ci` `chore` `style` `revert`
- `scope` 는 선택. 쓰면 변경된 모듈·디렉토리 이름(`auth`, `api`, `ui`). 여러 모듈에 걸치면 생략한다.
- 호환성이 깨지는 변경은 `type` 뒤에 `!` 를 붙이고(`feat(api)!:`), 본문 특이사항에 무엇이 깨지는지 쓴다.
- 요약은 50자 안팎, 마침표 없이, **명사형으로 끝낸다**("~추가", "~수정", "~제거"). "~했습니다", "~함" 같은 서술형 어미는 제목에 쓰지 않는다.
- 요약은 결과를 말한다. "로그인 버그 수정 시도"가 아니라 "토큰 만료 경계값 검사 수정".

`type` 이 내용과 맞는지도 본다. 동작이 바뀌지 않는 구조 변경을 `feat` 로 달거나, 버그 수정을 `refactor` 로 다는 경우가 흔하다.

## 본문

- 제목만으로 충분한 작은 커밋(오타, 의존성 버전 올림)은 본문을 생략해도 된다. 생략된 본문을 지적하지 않는다.
- 본문은 제목과 빈 줄 하나로 떨어뜨린다.
- 개조식 불릿으로 쓰고, 어미는 한 메시지 안에서 통일한다("~함" 또는 "~한다" 중 하나).
- **왜**를 쓴다. 무엇을 바꿨는지는 diff 가 보여주지만, 왜 바꿨는지는 메시지에만 남는다.
- 이슈 번호가 있으면 마지막 줄에 `Refs: #123` 또는 `Closes: #123`.

## 예시

원문:

```
fix: 버그 수정

로그인 관련해서 문제가 있어서 해당 부분을 수정하는 작업을 진행하였습니다.
처음에는 캐시 문제인 줄 알고 캐시를 지워봤는데 안 돼서 코드를 보니
exp 비교하는 부분이 잘못되어 있었습니다. 깔끔하게 고쳤습니다.
```

검수:

- **가시성**: 수정 — 제목에서 무엇을 고쳤는지 알 수 없음, 본문이 문단 덩어리
- **자연스러운 한국어**: 수정 — "수정하는 작업을 진행하였습니다" → "수정함"
- **과잉 설명**: 수정 — 캐시를 의심했던 과정, "깔끔하게 고쳤습니다" 자기 평가 제거
- **지칭 표현**: 수정 — "로그인 관련", "해당 부분" → `auth/middleware.ts` 의 JWT 만료 검사

수정안:

```
fix(auth): JWT 만료 경계값 검사 수정

- exp 와 현재 시각이 같은 요청을 유효로 판정해 만료 직전 1초 구간에서 401 이 산발적으로 발생함
- 만료 검사를 `exp < now` 에서 `exp <= now` 로 바꿔 경계 시각을 만료로 처리함
```
