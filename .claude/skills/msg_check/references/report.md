# 진행 보고 규칙

`msg_check` 의 참조 문서. 검수 대상이 슬랙·데일리·주간 진행 보고일 때 읽는다.

---

## 독자

진행 보고의 독자는 대개 동료, 리드, 다른 팀이다. 이들은 코드를 보지 않는다. 알고 싶은 건 **지금 어디까지 왔고, 막힌 게 있는지, 자기가 뭘 해줘야 하는지**다. 그래서 커밋·PR 보다 기술 세부를 더 덜어내고, 상태와 요청을 더 앞에 둔다.

## 구조

```
<한 줄 요약 — 오늘/이번 주 가장 중요한 진척>

• 작업: <작업한 문제 및 기능>
• 결과: <완료 / 진행 중(n%) / 막힘 — 무엇이 달라졌나>
• 특이사항: <막힌 점, 도움 요청, 일정 변동>   ← 있을 때만
```

- 작업이 여러 개면 작업 단위로 위 블록을 반복한다. 한 블록에 여러 작업을 섞지 않는다.
- 슬랙에 올리는 글이면 마크다운 헤더(`##`) 대신 굵은 글씨와 `•` 불릿을 쓴다. 슬랙은 헤더를 렌더링하지 않는다.
- 도움 요청은 특이사항 맨 앞에, 누구에게 무엇을 요청하는지 이름으로 쓴다("@민수 스테이징 DB 접근 권한 필요").

## 진행 보고에서 특히 자주 보이는 문제

- **상태가 없음** — 무엇을 했는지만 있고, 끝났는지 진행 중인지 알 수 없음. 가시성 문제로 지적한다.
- **내부 용어** — 팀 밖 독자가 읽는데 함수명·브랜치명·티켓 약어로만 지칭함. 지칭 표현 문제로 지적하고, 독자가 알아볼 기능 이름으로 바꾼다. 같은 팀 채널이면 그대로 둔다 — 독자가 누군지 모르면 묻는다.
- **활동 나열** — "회의 참석, 코드 리뷰, 슬랙 답변". 결과가 없는 활동은 보고할 진척이 아니다. 과잉 설명으로 보고 빼거나 한 줄로 합친다.
- **변명형 서술** — 늦어진 이유를 길게 쓰는 문단. 특이사항에 "일정 변동: A 때문에 목요일 → 다음 주 월요일" 한 줄로 줄인다.

## 예시

원문:

```
오늘은 어제 얘기했던 그거 계속 작업했고요, 거의 다 된 것 같은데
아직 테스트는 진행하지 못한 상태입니다. 그리고 회의도 두 개 들어갔고
코드리뷰도 좀 했습니다. 내일은 마무리 할 수 있을 것 같습니다.
```

수정안:

```
결제 웹훅 재시도 로직 구현 거의 마무리 — 내일 테스트 후 완료 예정

• 작업: 결제 웹훅 실패 시 지수 백오프로 재시도
• 결과: 진행 중 — 구현 완료, 테스트 미진행
```

("어제 얘기했던 그거"가 결제 웹훅 재시도라는 건 대화 맥락에서 확인된 경우에만 쓴다. 확인되지 않으면 `<?>` 로 두고 묻는다.)
