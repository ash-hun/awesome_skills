# 어색한 표현·번역투 목록

`msg_check` 의 참조 문서. "자연스러운 한국어" 기준을 검수할 때 대조한다.

목록은 판단의 출발점이지 금지어 사전이 아니다. 문맥상 자연스러우면 그대로 둔다 — 예를 들어 "~에 대한"은 "API 에 대한 접근 권한"처럼 명사를 이어줄 때는 자연스럽다. 기준은 하나다: **같은 뜻을 더 짧고 직접적인 한국어로 말할 수 있는가.**

---

## 1. 동사를 명사로 감싸기

동작을 명사로 만들고 "진행하다/수행하다/실시하다"를 붙이는 구조. 가장 흔하고, 고치면 가장 많이 짧아진다.

| 원문 | 고친 표현 |
|---|---|
| 테스트를 진행했습니다 | 테스트했습니다 |
| 리팩터링 작업을 수행함 | 리팩터링함 |
| 수정하는 작업을 진행하였습니다 | 수정했습니다 |
| 배포를 실시할 예정 | 배포할 예정 |
| 검토가 이루어졌습니다 | 검토했습니다 |

## 2. 이중 피동·불필요한 피동

| 원문 | 고친 표현 |
|---|---|
| 추가되어졌습니다 | 추가했습니다 / 추가됐습니다 |
| 사용되어지는 함수 | 쓰이는 함수 |
| 에러가 발생되었습니다 | 에러가 발생했습니다 |
| ~로 보여집니다 | ~로 보입니다 |

행위자가 분명하면(작성자 본인) 능동으로 쓴다. 커밋·PR 에서 행위자는 거의 항상 작성자다.

## 3. 영어 구문 직역

| 원문 | 고친 표현 | 원래 영어 |
|---|---|---|
| ~하는 것이 가능합니다 | ~할 수 있습니다 | it is possible to |
| ~를 가지고 있습니다 | ~가 있습니다 | have |
| ~에 있어서 | ~에서 / ~할 때 | in terms of |
| ~를 통해 해결 | ~로 해결 | through |
| ~함에 따라 | ~해서 | as |
| ~에 의해 처리됨 | ~가 처리함 | by |
| 가장 중요한 것 중 하나는 | 특히 중요한 것은 | one of the most |
| 그것은 ~ | (주어 생략) | it |

## 4. "~에 대한 / ~에 관한" 남용

명사 사이에 끼어 문장을 늘인다. 목적어로 바꾸거나 뺀다.

| 원문 | 고친 표현 |
|---|---|
| 로그인에 대한 수정 | 로그인 수정 |
| 성능에 대한 개선 작업 | 성능 개선 |
| 에러 처리에 관한 부분을 변경 | 에러 처리를 변경 |

## 5. 의미 없는 복수 "~들"

한국어는 복수를 표시하지 않아도 된다. "여러 파일들", "모든 테스트들"은 "여러 파일", "모든 테스트"로.

## 6. 영어 동사 + 한국어 어미

| 원문 | 고친 표현 |
|---|---|
| fix 했습니다 | 고쳤습니다 |
| refactoring 진행 | 리팩터링함 |
| update 됨 | 갱신함 |
| merge 할 예정 | 병합할 예정 (또는 "머지할 예정" — 팀 관용이면 유지) |

명사로 굳은 기술 용어(API, 캐시, 커밋, 머지, 배포, 롤백)는 그대로 둔다. 바꾸는 건 영어 **동사**를 한국어 어미로 억지로 활용한 경우다.

## 7. 과한 경어·의례 표현

작업 메시지는 공문이 아니다.

| 원문 | 고친 표현 |
|---|---|
| ~하였사오니 참고 부탁드립니다 | ~했습니다 |
| 확인 부탁드리겠습니다 | 확인 부탁드립니다 |
| ~하도록 하겠습니다 | ~하겠습니다 |

## 8. 모호한 부사·헤지

"좀", "약간", "거의", "아마", "~인 것 같습니다". 실제로 불확실하면 남기되, 불확실한 대상을 분명히 한다("아마 될 것 같습니다" → "스테이징에서 미확인"). 확실한데 습관처럼 붙인 헤지는 뺀다.
