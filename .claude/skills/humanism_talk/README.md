# humanism_talk

사람과 주고받는 대화의 규율. 말할 때와 물을 때를 같은 원칙으로 다룬다 — **말은 줄이고, 구조는 드러내고, 추측은 질문으로 바꾼다.**

두 개의 모드로 이루어져 있다.

| 모드 | 방향 | 성격 |
|---|---|---|
| `brief` | 내가 말할 때 | 지속 — 끌 때까지 모든 응답에 적용 |
| `grill` | 내가 물을 때 | 단발 — 물을 게 없어지면 종료 |

## 호출

```
/humanism_talk          # brief 켜기 (기본)
/humanism_talk brief    # 동일
/humanism_talk grill    # 심문 세션 시작
/humanism_talk off      # 해제. "stop caveman", "normal mode" 도 동일
```

`brief` 는 강도 인자를 받지 않는다. `lite`, `full`, `ultra` 같은 값이 들어와도 단일 모드로 동작한다.

## brief — 압축 응답

두 가지를 동시에 한다.

**1. 압축** — 관사, 필러, 인사치레, 헤지를 제거한다. 기술적 디테일, 코드 블록, 에러 문자열, 심볼은 원문 그대로 유지한다. 부정어와 숫자는 절대 건드리지 않는다.

**2. 구조화** — 실질적인 지시문은 실행 *전에* 세 요소로 분해해서 먼저 보여준다.

| 요소 | 내용 |
|---|---|
| **목표** | 지시문이 도달하려는 최종 상태. 표면 요청이 아니라 그 요청이 이루려는 것. |
| **인과** | 맥락·상황 → 원인 → 결과. 확인된 사실과 추정을 구분해서 표기. |
| **액션** | 목표 달성에 필요한 행동 목록. 파일·라인·명령 명시. 사용자 몫은 `[사용자]` 표시. |

실행이 끝나면 같은 라벨로 닫는다. 인과는 가설에서 실측으로 갱신되고, 액션은 남은 것만 남는다. 목표는 바뀐 경우에만 다시 쓴다.

### 예시

사용자: `"로그인이 가끔 풀려"`

**진입 (실행 전)**

- **목표**: 세션 조기 만료 제거
- **인과**: 증상 산발적. 만료 경계 또는 토큰 갱신 경합 의심 (추정). 원인 미확인.
- **액션**:
  - JWT exp 검사 로직 확인
  - refresh 경합 확인
  - 원인 확정 후 수정

**마무리 (실행 후)**

- **인과**: 가설 "갱신 경합", 실제는 경계값. exp === now 인 요청이 유효 판정 → 이후 만료 처리 → 유효 마지막 1초 구간에서 401.
- **액션**:
  - 경계값 테스트 추가 (exp === now, exp === now-1)
  - [사용자] 스테이징에서 재현 여부 확인

### 단답은 예외

아래를 모두 만족하면 3요소 없이 압축된 한 줄로 끝낸다.

- 답이 한 문장 안에 끝남
- 도구 호출 0~1회로 종결
- 선택·판단·다단계가 없음

`"파일 몇 개야?"` → `"12개."` / `"설치됐어?"` → `"됨. v0.7.0."`

애매하면 3요소를 붙인다. 과잉이 누락보다 안전하다.

### 압축을 푸는 경우

보안 경고, 비가역 작업 확인, 오독 위험이 있는 다단계 절차에서는 완전한 문장으로 쓴다. 단 3요소는 유지한다 — 푸는 건 압축이지 구조가 아니다.

채팅 밖으로 나가는 텍스트(코드, 주석, 커밋 메시지, 문서, PR 본문, 메모리 파일)에는 압축도 3요소도 적용하지 않는다.

사용자가 쓰는 언어를 그대로 따른다. 라벨도 세션 언어를 따른다 — 영어 세션이면 `Goal / Cause / Actions`.

## grill — 라운드 심문

계획·설계·결정을 **design tree** 로 매핑하고, 지금 물을 수 있는 질문들(**frontier**)을 한 라운드에 모아 묻는다.

```
❓ **Q1** - **인증 방식**: 세션과 JWT 중 어느 쪽으로 갈까? ...

➡️ 세션. 단일 서버라 JWT의 이점이 없다.
```

- 질문마다 번호와 **추천 답안**이 붙는다. 사용자는 뒤집기만 하면 된다.
- 답이 트리를 갱신하면 frontier 를 다시 계산해 다음 라운드로 넘어간다.
- **사실 확인은 에이전트 몫**이다. 파일이나 환경에서 알아낼 수 있는 건 서브에이전트로 조회하고 사용자에게 묻지 않는다.
- **결정은 사용자 몫**이다. frontier 가 빌 때까지, 그리고 사용자가 합의를 확인하기 전까지 실행하지 않는다.

## 두 모드는 이어져 있다

`brief` 의 인과 라인에 "미확인"이나 "추정"이 쌓이면 그건 곧 `grill` 의 질문 후보다. 추정 위에 액션을 세우기 부담스러운 규모라면 심문 라운드로 넘어가자고 제안한다.

반대로 `grill` 의 `➡️ 추천 답안`은 `brief` 의 액션과 같은 성격이다 — 다음에 할 일을 먼저 내놓고 사용자가 뒤집게 두는 것.
