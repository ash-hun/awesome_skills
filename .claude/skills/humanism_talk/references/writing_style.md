# 한국어 문체: 표현 사전

`humanism_talk` 스킬의 참조 문서. `brief.md` 의 "한국어 문장" 절이 요약본이고, 이 파일이 전체 사전이다. 사람이 읽을 한국어 산문을 쓰거나 검수할 때 읽는다. 문서, README, PR 본문, 메일, 블로그, 강의 자료, 발표 자료가 해당한다.

적용 범위는 사람이 읽는 한국어 텍스트 전부다. 코드와 코드 주석은 대상이 아니다. 지시문서(CLAUDE.md, SKILL.md)와 도식은 불릿, 헤딩, 굵게 같은 **구조**만 예외이고, 그 안의 문장에는 이 규칙을 적용한다.

목록은 판단의 출발점이다. 문맥상 자연스러우면 그대로 둔다. 기준은 하나다: **같은 뜻을 더 짧고 직접적인 한국어로 말할 수 있는가.**

## 핵심 원칙

- 동사와 형용사 어근을 살린다. 명사로 감싸고 "진행하다", "가지고 있다"를 붙이지 않는다.
- 형식명사(것, 점, 바, 수)로 끝나는 문장을 줄인다.
- 추상 주어를 구체 행위자로 바꾼다. 사건이나 개념을 주어로 세우지 않는다.
- 평가 대신 사실을 쓴다. "분명하다", "선명해졌다", "폭발적" 대신 수치나 구체 결과를 쓴다.
- 단문과 복문을 섞어 리듬을 만든다. 같은 길이, 같은 접속사가 문단마다 반복되면 AI 톤으로 읽힌다.

## 등급과 허용 횟수

- **오류**: 0회. 발견하면 고친다.
- **제안**: 기본 0회. 표에 허용 횟수가 따로 적힌 항목만 문서당 그 횟수까지 둔다. 넘으면 다양화한다.
- 고객 대면 문서(책, 강의안, 블로그, 발표 자료, 메일)는 기준을 엄격하게 본다. 내부 메모와 대화체 캡션은 톤이 맞으면 표현 순화 항목을 한두 번 허용한다.

## 비유 직역

영어 관용구를 그대로 옮긴 비유. 한국어 독자에게는 뜻이 한 번 꺾여 들어온다.

| 걸리는 예 | 고친 예 |
|---|---|
| 현장에서 넘어진 것 | 현장에서 막힌 점 |
| 비싼 티어가 산 것은 | 비싼 티어로 얻은 것은 |
| 좋은 다음 걸음입니다 | 다음에 할 일입니다 |
| 하나만 가져간다면 | 한 가지만 기억한다면 |
| 문제를 모델이 녹여 버린다 | 모델이 문제를 단숨에 푼다 |
| 보내 놓고 잊는 방식으로 | 끝나기를 기다리지 않고 다음 단계로 넘어가는 방식으로 |
| 러닝 커브가 올라간다 | 배우기 어려워진다 |
| 이 문제를 도구로 받았다 | 이 문제를 도구로 해결했다 |
| 수학에서 능력이 먼저 튄다 | 수학에서 성능이 두드러진다 |

모두 제안 등급, 허용 0회.

| 걸리는 예 | 고친 예 | 허용 |
|---|---|---|
| 긴장으로부터의 해방 | 긴장에서 벗어남 | 0 |
| 채팅과의 대비 | 채팅과 비교하면 | 0 |
| Claude Code로의 전환의 장점 | Claude Code로 바꾸면 좋은 점 | 2 |

## AI 상투구

모델이 쓴 티가 가장 많이 나는 구간이다. 평가어와 도입구를 지우고 사실을 쓴다.

| 걸리는 예 | 고친 예 | 등급 | 허용 |
|---|---|---|---|
| ~라는 사실이 선명해졌습니다 | 사실을 단언한다. "남은 것이 없었습니다" | 오류 | 0 |
| 시사하는 바가 큽니다 | 무엇을 시사하는지 구체로 쓴다 | 오류 | 0 |
| 결론적으로 | 지우거나 구체 동사로 | 오류 | 0 |
| 폭발적인 호응 | 구체 수치로 | 오류 | 0 |
| 순서를 뒤집는다, 관점을 뒤집는다 | 순서를 바꾼다, 반대로 본다 | 오류 | 0 |
| 요약하면 두 가지입니다 | 도입구를 지우고 바로 쓴다 | 제안 | 0 |
| 크게 세 가지로 나눌 수 있습니다 | 도입구를 지우고 바로 열거한다 | 제안 | 0 |
| 혁신적인 방식으로 | 무엇이 달라졌는지 사실로 | 제안 | 0 |
| 주목할 만한 변화입니다 | 지우거나 구체 결론으로 | 제안 | 0 |
| 필요한 것은 속도가 아니라 방향입니다 | 방향이 필요합니다 | 제안 | 0 |
| 결국 비용 문제로 이어진다 | 인과 경로를 구체로 쓴다 | 제안 | 1 |
| 잘 돌아갑니다. 과제도 남아 있습니다. | 문패 문장을 지우고 실제 과제를 첫 문장으로 | 제안 | 0 |
| 부작용이 시장을 잠식합니다 | 점유율을 뺏습니다 (과장 동사를 평서로) | 제안 | 0 |

## 표현 순화

구어성이나 폭력성이 강한 동사. 문서 톤을 흐트러뜨린다.

| 걸리는 표현 | 대체 |
|---|---|
| 박아두다, 박다, 박힌 | 저장하다, 기입하다, 넣어두다, 등록하다, 고정하다 |
| 갈아끼우다 | 교체하다, 바꾸어 넣다 |
| 때려박다 | 한 번에 입력하다, 일괄 등록하다 |
| 깔다 (도구를) | 설치하다 |
| 던지다 (파일, 프롬프트를) | 첨부하다, 입력하다, 전달하다 (대화체에서 한 번 정도는 허용) |
| 뒤집다 (관점, 순서를) | 바꾸다, 반대로 하다 |

## 문장부호

- 긴 대시(—)를 쓰지 않는다. en dash(–)는 영문 숫자 범위에만 쓴다.
- 가운뎃점(·)을 쓰지 않는다. 대시의 대체로도 쓰지 않는다.
- 대체: 쉼표, 콜론, 괄호, 또는 마침표로 끊고 새 문장. 의미에 맞게 고른다.

## 사전으로 못 잡는 패턴

검색으로는 안 걸리고 문맥으로만 보인다. 쓸 때와 검수할 때 직접 본다.

- 지시 대상이 없는 대명사(그는, 그것은)
- 사건이나 개념을 주어로 세운 의인화(질문을 던진다, 데이터가 말해준다)
- 변환 슬로건("X에서 Y로")
- 동의어를 겹친 수식("빠르고 신속한")
- 양쪽을 다 챙기는 안전 균형 어휘("장점과 단점 모두")
- 문단마다 같은 접속사로 시작하기
- 명사 연쇄("문제 해결 능력 향상 방안")

## 검수 절차

대외로 나가는 문서는 게시 전에 아래를 확인한다.

1. 문장부호 잔여 확인. 결과가 0건이어야 한다. 코드 블록 안은 제외하고 본다.
   ```
   grep -nP "[\x{2014}\x{00B7}]" <파일>
   grep -nP "\x{2013}" <파일>    # 숫자 범위 외 사용 확인
   ```
2. 표현 순화와 오류 등급 항목 검색.
   ```
   grep -nE "박아|박힌|박혀|갈아끼|때려박|되어진|보여지|시사하는 바|결론적으로|선명해졌|폭발적|뒤집" <파일>
   ```
3. 제안 등급 항목은 허용 횟수 안인지 센다.
4. 사전으로 못 잡는 패턴을 문단 단위로 읽으며 확인한다.

## 사전 유지

사용자가 새로 거슬리는 표현을 지적하면 이 파일의 해당 표에 추가한다. 같은 표현을 두 곳에 두지 않는다.
