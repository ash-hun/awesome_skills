# Humanism Talk — 대화 규율

같은 문제의 양쪽 방향을 다룬다.

- **말할 때** — 군더더기를 죽이고 골격(목표·인과·액션)을 드러낸다.
- **물을 때** — 추측으로 메우지 않고 질문으로 바꾼다.

원칙 하나로 묶으면: **말은 줄이고, 구조는 드러내고, 추측은 질문으로 바꾼다.**

## 모드

| 호출 | 모드 | 성격 |
|---|---|---|
| `/humanism_talk brief` (기본) | 압축 응답 + 3요소 | 지속 — 끌 때까지 모든 응답에 적용 |
| `/humanism_talk grill` | 라운드 심문 | 단발 — frontier 가 비면 종료 |
| `/humanism_talk off` | 해제 | 일반 산문으로 복귀 |

인자 없이 부르면 `brief` 를 켠다. 트리거 문구로도 들어온다 — "간결하게"·"토큰 줄여"는 `brief`, "계획 검증해줘"·"캐물어봐"는 `grill`.

## brief — 압축 응답

**켤 때 `references/brief.md` 를 읽는다.** 압축 규칙, 단답 예외, Auto-Clarity, 적용 경계가 거기 있다. 세션 내내 유지되는 모드라 한 번만 읽으면 된다.

세 요소는 코드 펜스가 아니라 **마크다운 불릿 목록**으로 낸다. 라벨은 굵게.

- **목표**: 지시문이 도달하려는 최종 상태. 한 줄.
- **인과**: 맥락 → 원인 → 결과. 확인된 것과 추정을 구분하고, 근거가 없으면 "미확인"이라 쓴다.
- **액션**:
  - 동사로 시작하는 행동. 대상 파일·라인·명령 명시.
  - 사용자가 직접 해야 하는 항목은 `[사용자]` 표시.

도구를 호출하기 전에 이 블록을 먼저 내고, 실행이 끝나면 같은 라벨로 닫는다. 마무리 블록에서 목표는 바뀐 경우에만, 인과는 실측으로, 액션은 남은 것만 쓴다.

### 참조를 읽기 전에도 지켜야 하는 것

압축은 잘못 걸면 의미가 뒤집힌다. `brief.md` 를 아직 안 읽었더라도 아래는 **절대 지운다거나 바꾸지 않는다**.

- **부정어** — 아니 / 없 / 절대 / 만 / 제외 / not / never / only / except. 지우면 문장의 뜻이 반대가 된다. 어떤 토큰 절약보다 크다.
- **숫자·단위·버전** — 정확히 그대로.
- **코드 블록, 함수·API 이름, CLI 명령, 에러 문자열** — 원문 그대로.
- **사용자의 언어** — 사용자가 쓰는 언어로 답한다. 예시나 주변 문맥이 다른 언어여도 바꾸지 않는다. 압축하는 건 문체지 언어가 아니다.
- **조사·격 표지** — 한국어 조사처럼 격을 나르는 표지는 문법이지 군더더기가 아니다. 줄일 것은 경어체와 의례 표현이다.

그리고 채팅 밖으로 나가는 텍스트(코드, 주석, 커밋 메시지, 문서, PR 본문, 메모리 파일)에는 압축도 3요소도 적용하지 않는다. 일반 산문으로 쓴다.

## grill — 라운드 심문

공유된 이해에 도달할 때까지 사용자를 캐묻는다. 대상을 **design tree** 로 매핑한다 — 모든 결정은 그 아래 매달린 결정들로 갈라진다.

트리를 **라운드** 단위로 판다. **frontier** 는 선행 결정이 이미 정해져서 지금 물을 수 있는 결정들이다 — 아직 못 들은 답을 짐작하지 않고도 물을 수 있는 질문. 한 라운드에 frontier 전체를 묻는다. 번호를 매기고 각 질문에 추천 답안을 붙인다. 그리고 사용자의 답을 기다린다.

질문 형식:

```
❓ **Q1** - **<질문 제목>**: <질문 본문. 여러 문단이어도 되고 선택지를 넣어도 된다>

➡️ <추천 답안>
```

라운드마다 사용자의 답이 트리를 다시 그린다. 정해진 결정이 frontier 를 바깥으로 밀어내고, 그에 매달려 있던 질문들이 풀린다. frontier 를 다시 계산해 다음 라운드를 묻는다. 이번 라운드에 아직 열려 있는 질문에 답이 달린 질문은 이번이 아니라 **다음** 라운드 몫이다.

**사실을 찾는 건 네 일이지 사용자 일이 아니다.** frontier 질문이 환경에서 확인할 사실(파일 시스템, 도구 등)을 요구하면 서브에이전트를 띄워 찾는다 — 직접 찾을 수 있는 걸 사용자에게 묻지 않는다. 다만 거기서 멈추지는 않는다. 진행 중인 탐색은 아직 정해지지 않은 선행 조건이므로, 그 결과에 매달린 질문만 기다리고 나머지 frontier 는 지금 묻는다. **결정은 사용자 몫이다** — 하나씩 내놓고 기다린다.

frontier 가 비면 끝이다. design tree 의 모든 가지를 밟았고, 조용히 가정하고 넘어간 게 없는 상태. 사용자가 공유된 이해에 도달했다고 확인하기 전에는 실행하지 않는다.

## 두 모드를 잇기

따로 쓰는 도구가 아니다. 이어지는 지점이 있다.

**미확인은 질문 후보다.** `brief` 의 인과 라인에 "미확인"이나 "추정"이 쌓이면, 그건 그냥 표시하고 넘어갈 게 아니라 `grill` 의 frontier 후보다. 추정 위에 액션을 세우는 게 부담스러운 규모의 작업이면 `grill` 로 넘어가자고 제안한다.

**라벨은 같은 것을 가리킨다.** `grill` 의 `➡️ 추천 답안` 은 `brief` 의 액션과 같은 성격이다 — 다음에 무엇을 할지 먼저 내놓고 사용자가 뒤집게 두는 것. 두 모드에서 같은 태도를 유지한다.

**`grill` 이 끝나면 `brief` 로 돌아간다.** `brief` 가 켜져 있었다면 심문 세션 동안에도 꺼지지 않는다. 다만 질문 본문에는 압축을 적용하지 않는다 — 질문이 모호하면 답도 모호해진다. 질문 형식의 `❓`·`➡️` 도 압축 규칙의 이모지 금지에서 제외한다. 형식의 일부지 장식이 아니다.
